# Postify

A full-stack social media application built with the MERN stack where users can create and share image-based posts, interact through likes and comments, manage personalized profiles, and use the application across responsive light and dark interfaces.

Postify was built as a complete full-stack project covering frontend development, REST API design, authentication, authorization, image storage, state management, responsive UI development, production deployment, and production-specific issues such as CORS and cross-site cookie configuration.

## Authentication Flow

Postify uses JWT-based authentication with HTTP-only cookies.

1. The user registers or logs in.
2. The backend validates the credentials.
3. A JWT is generated containing the user's identifier.
4. The token is stored in an HTTP-only cookie.
5. Axios sends authenticated requests using `withCredentials: true`.
6. Authentication middleware validates the cookie before allowing access to protected routes.
7. Ownership checks prevent users from modifying resources they do not own.
8. Production cookie configuration uses secure cross-site cookie settings for the separately deployed frontend and backend.

## State Management

Postify uses React Context API to manage application-level state.

### AuthContext

Responsible for:

- Current authenticated user
- Authentication initialization
- Login state
- Persistent session restoration
- Logout flow

### PostsContext

Responsible for:

- Feed posts
- Like and unlike updates
- Comments
- Post creation
- Post deletion
- Modal state
- Profile-related post synchronization

Centralizing shared state reduces unnecessary API refetching and keeps UI updates synchronized across different components.

## Environment Variables

Create a `.env` file inside the `backend` directory:

```env
PORT=4000

MONGO_URI=your_mongodb_connection_string

JWT_SECRET=your_jwt_secret

CLOUDINARY_CLOUD_NAME=your_cloudinary_cloud_name
CLOUDINARY_API_KEY=your_cloudinary_api_key
CLOUDINARY_API_SECRET=your_cloudinary_api_secret

FRONTEND_URL=http://localhost:5173
```

Create a `.env` file inside the `frontend` directory:

```env
VITE_API_URL=http://localhost:4000
```

Never commit `.env` files containing credentials or secrets.

## Running Locally

### 1. Clone the Repository

```bash
git clone https://github.com/Jatin915/Postify.git
cd Postify
```

### 2. Install Backend Dependencies

```bash
cd backend
npm install
```

Create the backend `.env` file and add the required environment variables.

Start the backend development server:

```bash
npm run dev
```

The backend runs locally on:

```text
http://localhost:4000
```

### 3. Install Frontend Dependencies

Open another terminal:

```bash
cd frontend
npm install
npm run dev
```

The frontend runs locally on:

```text
http://localhost:5173
```

## Production Deployment

Postify uses separate frontend and backend deployments.

```text
React Frontend
      │
      │ HTTPS requests with credentials
      ▼
Express REST API
      │
      ├──────────────► MongoDB Atlas
      │
      └──────────────► Cloudinary
```

### Frontend

Deployed on Vercel with:

```env
VITE_API_URL=your_render_backend_url
```

### Backend

Deployed on Render with production environment variables including:

```env
NODE_ENV=production
FRONTEND_URL=your_vercel_frontend_url
MONGO_URI=your_mongodb_atlas_uri
```

The production setup required configuring CORS credentials and secure cross-site cookies because the frontend and backend are deployed on different domains.

## Key Technical Challenges

### Cross-Site Authentication in Production

The frontend and backend are deployed on different domains.

This required configuring:

- CORS with credentials
- Axios `withCredentials`
- HTTP-only cookies
- `SameSite=None` in production
- Secure cookies in production
- Matching cookie options during logout

### Shared State Synchronization

Likes, comments, post creation, deletion, and profile updates affect multiple components.

Centralized state management through Context API was used to keep the interface synchronized without unnecessary page reloads.

### Image Upload Pipeline

Post and profile images are uploaded through the backend and stored using Cloudinary.

The application handles:

```text
Client File Selection
        │
        ▼
Multipart Form Data
        │
        ▼
Multer Middleware
        │
        ▼
Cloudinary Upload
        │
        ▼
Image URL Stored in MongoDB
        │
        ▼
Responsive Image Rendering
```

### Production Deployment

Deploying the application exposed issues that were not visible during local development, including:

- Missing production dependencies
- CORS origin configuration
- Cross-site cookie behavior
- Environment variable management
- MongoDB Atlas connectivity
- SPA routing configuration

Resolving these issues was an important part of taking Postify from local development to a deployed full-stack application.
